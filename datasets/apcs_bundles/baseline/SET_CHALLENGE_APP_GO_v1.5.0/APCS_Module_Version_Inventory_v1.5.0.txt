Notes
-----
  - Frontend bumps the minor for the new "CI / CD Pipeline" tab,
    the auto-refresh "Live" indicator and the in-dashboard approval
    flow.
  - Backend bumps the minor because of the new `ci_bridge` router
    and the additional environment variables consumed at startup
    (`CI_BRIDGE_REPO`, `CI_BRIDGE_TOKEN`, `CI_BRIDGE_BRANCH`).
  - `backend.ci_bridge` is a brand-new module; it depends only on
    the Python standard library plus FastAPI and Pydantic, no new
    third-party dependency was introduced.
  - `scripts/eval/run_ci_analysis` is now self-aware: its own path
    is excluded from the BLOCKER marker scan to prevent the script
    from flagging itself.
  - The Helm chart bumps the minor because `deployment.yaml` now
    references `ci_bridge_token` from the existing
    `challenge-app-secrets` Secret, and `values.yaml` exposes a
    new `env.ci_bridge_repo` field.
  - The CI workflow bumps the minor because `analyze-pre-prod` now
    also runs on `push` events (previously it was release-only) and
    because the `approve-test` / `approve-prod` jobs are wired to
    the `hitachi-test-approval` and `hitachi-prod-approval`
    GitHub environments respectively.
